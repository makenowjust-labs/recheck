This page collects vulnerabilities found with `recheck` and projects that use it.
If `recheck` helped you to find a vulnerability or you use it in your project, please tell us in the [Reports](https://github.com/makenowjust-labs/recheck/discussions/categories/reports) discussion category.

## Projects using recheck

### Testing their own regular expressions

- [Zod](https://github.com/colinhacks/zod) runs `checkSync` over every regular expression it ships in its test suite, including the parameterized ones.
- [marked](https://github.com/markedjs/marked) has a `test:redos` script that checks every tokenizer rule with `check` and prints the vulnerable ones.
- [path-to-regexp](https://github.com/pillarjs/path-to-regexp) asserts in its tests that the regular expressions it generates are reported as safe.

### Guarding regular expressions built at runtime

- [Civitai](https://github.com/civitai/civitai) rejects a `pattern` in a submitted settings manifest unless `check` reports it as safe.
- [Condo](https://github.com/open-condo-software/condo) checks the keys of a message template with `checkSync` before turning them into regular expressions.
- [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter), an MCP adapter for the Pi coding agent, rejects a regular expression query from the agent unless `checkSync` reports it as safe.

### Linting with eslint-plugin-redos

- [core-js](https://github.com/zloirock/core-js) enables `redos/no-vulnerable` as an error over its whole code base, and marks the few regular expressions it disables the rule for as safe in the source.
- [markdownlint](https://github.com/DavidAnson/markdownlint) enables `redos/no-vulnerable` as an error with a long `timeout`.
- [pjax-api](https://github.com/falsandtru/pjax-api) enables it as an error with `ignoreErrors: false`, so that even an unknown result fails the lint.
- [Crosshare](https://github.com/crosshare-org/crosshare) enables it in the ESLint configuration of its app and its cloud functions.
- [better-auth-harmony](https://github.com/GeKorm/better-auth-harmony) turns the recommended configuration on with an environment variable, so that the slower check runs on demand.
- [Mailflow](https://github.com/maathimself/mailflow) keeps a separate audit configuration to run before adding a new text-processing regular expression.

### Services and other tools

- [devina.io ReDoS Checker](https://devina.io/redos-checker) is an online checker powered by `recheck`.
- [Gixy-Next](https://github.com/dvershinin/gixy), a scanner for nginx configurations, checks the regular expressions in `location` directives through [`recheck-http-api`](https://github.com/MegaManSec/recheck-http-api). Its author compared ReDoS checkers and [found `recheck` to be the strongest](https://joshua.hu/regex-redos-recheck-nginx-gixy).
- The Datadog static analysis rule [`typescript-browser-security/regexp-non-literal`](https://docs.datadoghq.com/code_analysis/static_analysis_rules/typescript-browser-security/regexp-non-literal/) recommends `recheck` for checking regular expressions built at runtime.

As of October 2026, the `recheck` package is downloaded more than two million times a month from npm, and `eslint-plugin-redos` appears in the `package.json` of more than a hundred public repositories on GitHub.

## Tools built on recheck

- [recheck-cli](https://github.com/ndom91/recheck-cli) scans files for regular expressions and checks them.
- [redos-scanner](https://github.com/mizdra/redos-scanner) scans a GitHub repository.
- [gorecheck](https://github.com/hachi8833/gorecheck) is a command-line tool written in Go.
- [recheck-http-api](https://github.com/MegaManSec/recheck-http-api) exposes `recheck` as an HTTP endpoint.
- [recheck-esm](https://github.com/Regex-Radar/recheck-esm) repackaged `recheck` as ES modules before 4.6.1 shipped them.
