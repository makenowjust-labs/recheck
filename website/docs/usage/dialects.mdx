Describes the regular expression dialects that `recheck` supports, and what is common to all of them.

Each dialect has its own page on how it is checked:
[JavaScript](dialects/javascript.mdx) / [Python](dialects/python.mdx) / [Ruby](dialects/ruby.mdx) / [Java](dialects/java.mdx) / [.NET](dialects/dotnet.mdx) / [Perl](dialects/perl.mdx) / [PCRE](dialects/pcre.mdx).

## Choosing a Dialect

`recheck` checks a regular expression in the syntax and the semantics of one dialect.

The [`dialect`](parameters.mdx#dialect) parameter chooses it (the default is `javascript`).
It is the name of the dialect, or an object of the name and the dialect's settings (e.g. `{ "name": "python", "type": "bytes" }`).

The following shows how to check a pattern in the Python dialect.

<Tabs>
<TabItem value="cli" label="CLI">

```console
$ recheck --dialect=python '/^(a|a)*$/'
$ recheck --dialect=python --python-type=bytes '/^(a|a)*$/'
```

</TabItem>
<TabItem value="js" label="JavaScript">

```tsx
import { check } from "recheck";

await check("^(a|a)*$", "", { dialect: "python" });
await check("^(a|a)*$", "", { dialect: { name: "python", type: "bytes" } });
```

</TabItem>
<TabItem value="scala" label="Scala">

```scala
import codes.quine.labs.recheck.ReDoS
import codes.quine.labs.recheck.common.Parameters
import codes.quine.labs.resyntax.dialect.Dialect

ReDoS.check("^(a|a)*$", "", Parameters(dialect = Dialect.Python()))

```

:::note

The ESLint plugin (`eslint-plugin-redos`) checks JavaScript regular expressions only, so it has no `dialect` option.

:::

## Supported Dialects

| `dialect`                               | Engine that `recheck` follows                  | Matching unit                                      |
| --------------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| [`javascript`](dialects/javascript.mdx) | ECMAScript 2026 `RegExp` (V8)                  | `utf16`, or `utf16-code-point` with `u` or `v`     |
| [`python`](dialects/python.mdx)         | Python 3.15 `re`                               | `code-point` (`str`), or `byte` (`bytes`)          |
| [`ruby`](dialects/ruby.mdx)             | Ruby 4.0 `Regexp` (Onigmo)                     | `scalar-value` (`UTF-8`), or `byte` (`ASCII-8BIT`) |
| [`java`](dialects/java.mdx)             | Java 27 `java.util.regex.Pattern`              | `utf16-code-point`                                 |
| [`dotnet`](dialects/dotnet.mdx)         | .NET 10 `System.Text.RegularExpressions.Regex` | `utf16`                                            |
| [`perl`](dialects/perl.mdx)             | Perl 5.44 regular expressions                  | `code-point` (`utf8`), or `byte` (no `utf8`)       |
| [`pcre`](dialects/pcre.mdx)             | PCRE2 10.49 as PHP's `preg_*` functions use it | `byte`, or `scalar-value` with `u` or `(*UTF)`     |

## Matching Units

A (matching) unit is what a pattern reads as one character: `.` matches exactly one unit.

For example, `"😀"` (U+1F600) is one code point, two UTF-16 code units (`\ud83d\ude00`), and four bytes in UTF-8 (`\xf0\x9f\x98\x80`).
Which of them `.` matches depends on the dialect, and on its flags or the type of the input.

In JavaScript, a pattern reads UTF-16 code units, and the `u` or `v` flag makes it read code points.

{/* prettier-ignore */}
```js
"😀".match(/./)[0];  // => "\ud83d" (one UTF-16 code unit without `u`)
"😀".match(/./u)[0]; // => "😀" (one code point with `u`)
```

In Python, a pattern reads code points when it is a `str`, and bytes when it is a `bytes`, which also takes `bytes` as the input.

```python
re.match(".", "😀").group()           # => '😀' (one code point in a `str` pattern)
re.match(b".", "😀".encode()).group() # => b'\xf0' (one byte in a `bytes` pattern)
```

The matching units are of the following kinds, where the kinds of code points differ in what the surrogates are.

- `utf16`: UTF-16 code units.
- `utf16-code-point`: code points read from UTF-16, where a lone surrogate is a code point, but a high surrogate followed by a low surrogate is one code point.
- `code-point`: code points, where the surrogates are ordinary code points in any order.
- `scalar-value`: Unicode scalar values, which are the code points other than the surrogates.
- `byte`: bytes.

The table in [Supported Dialects](#supported-dialects) shows the matching units of each dialect.

## Syntax Limitations

`recheck` reads the whole syntax of the supported dialects.
It also reproduces, as far as possible, the errors that the engine reports after reading the syntax.
A pattern that the engine rejects is reported as `unknown` with an `invalid` error.

Some constructs are recognized, but the checkers do not handle them.
A pattern having one of them is reported as `unknown` with an `unsupported` error naming the construct (e.g. `a(?R)?` gives `unsupported syntax (RCall) at 1`).
Each dialect's page lists the constructs that it does not support (e.g. .NET's balancing groups).

The following are not supported in any dialect.

- Nesting deeper than 150 levels, where each group, look-around condition of a conditional, class, operand of a class set operation, and repeat of a repeat is one level (e.g. `(?:` repeated 151 times gives `Too deeply nested (limit 150) at 450`).

## Approximations

`recheck` models the matching of a naive backtracking engine.
Most engines have optimizations that make some vulnerable patterns fast, and `recheck` does not model them (see each dialect's page).

The following is what we measured with `^(a|a)*$` against `'a'.repeat(n) + '!'`.

- V8 (Node.js 26) and Python 3.15 take exponential time: about 2 seconds for `n = 24`.
- Ruby 4.0, Java 27, .NET 10 and Perl 5.44 finish in less than 1 ms even for `n = 28`.
- PHP 8.5 (PCRE2 10.49 with the default `pcre.backtrack_limit`) gives up with the backtrack limit error for `n = 20`.

So `recheck` reports `^(a|a)*$` as vulnerable in every dialect, but the attack is not effective on some engines.
[Runtime-Attack Verification](runtime-attack-verification.mdx) runs the attack string on the real engine, and it tells whether the attack works there.

The following approximations are common to the dialects.

- The Unicode data (properties, case mappings) is of Unicode 18.0, while the engines use Unicode 16 or 17.
- The automaton checker handles look-aheads, look-behinds, atomic groups, possessive quantifiers and conditionals on look-arounds.
  It handles back-references too, when the groups they refer to match at most `maxBackReferenceStrings` strings together, the pattern has no look-behind, and no look-around, atomic group or conditional has the groups (not in Perl, and in Ruby, neither a reference to a name shared by groups nor a case-insensitive one).
  The following are handled by the fuzz checker, which may show that the pattern is safe by an upper bound of its matching time without fuzzing:
  - non-atomic look-arounds, the other back-references, conditionals on groups, and the backtracking control verbs other than `(*FAIL)` and `(*MARK)`,
  - in a look-behind, an assertion that looks at more than the kinds of the characters next to it (e.g. Java's `\b`, and `$` in .NET and Python) and a look-ahead, and
  - in a look-behind that the engine matches forward from its possible starts (Java, PCRE, Perl and Python), an atomic group, a possessive quantifier, and an unbounded repetition (only Java allows it, e.g. `(?<=a*b)`).
